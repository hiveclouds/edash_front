# FR Dashboard Design Direction

## Product

FR Dashboard is an operational dashboard.

The interface should feel:
- purposeful
- technical
- clear
- practical
- trustworthy

Avoid making the application look like a generic AI-generated SaaS dashboard.

## Design priorities

Prioritize:

1. information hierarchy
2. operational clarity
3. fast scanning
4. readable data
5. meaningful visualization
6. consistent interaction
7. responsive usability

## Visual direction

Preserve the existing visual identity unless a redesign is explicitly requested.

Do not redesign the entire application merely to make it look "modern".

Visual changes should have a clear usability or communication purpose.

## Components

Use cards, tables, charts, badges, icons, and containers when they improve information grouping or interaction.

Avoid excessive card nesting.

Avoid decorative components that do not communicate useful information.

## Data visualization

Charts must represent real application data.

Never create fake metrics or decorative charts pretending to represent real data.

## Interaction

Buttons and controls must perform real functions.

Do not create visual controls that do nothing.

## Responsive

The interface must remain usable across:

- desktop
- laptop
- tablet
- mobile

Responsive behavior should reflow information appropriately rather than simply shrinking the desktop layout.

## Accessibility

Maintain:

- readable contrast
- keyboard usability
- visible focus states
- clear interaction states

## Implementation

Prefer the existing project architecture.

Do not introduce new frameworks or libraries unless explicitly requested.

Do not remove existing functionality during UI improvements.
